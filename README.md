# ИДЗ-3: умные цветы, вариант 14

Консольная программа для Linux на C11. Цветы сами запрашивают воду, садовники выбирают старейшую ожидающую заявку (FIFO). Четыре реализации используют одни и те же правила.

| Реализация | Кто запускает участников | Как передаются запросы и ответы | Семафоры POSIX |
|---|---|---|---|
| `fork-named` | Родитель через `fork()` | Разделяемая память POSIX | Именованные |
| `fork-unnamed` | Родитель через `fork()` | Разделяемая память POSIX | Неименованные, внутри неё |
| `independent-shm` | `server`, `flower` и `gardener` запускаются отдельно | Разделяемая память POSIX | Именованные |
| `independent-mq` | `server`, `flower` и `gardener` запускаются отдельно | Очередь сообщений POSIX | Именованные |

## Сборка и проверка

В Linux из папки проекта (компилятор C, Make; для тестов нужен Python 3):

```sh
make
make test
```

На Mac нужен Linux: в macOS нет используемых очередей POSIX. Для сборки и демонстрации на этом Mac можно открыть один контейнер в папке проекта, используя уже установленный локальный образ с GCC и Make:

```sh
podman run --rm -it --pull=never --platform linux/amd64 -v "$PWD:/src" -w /src localhost/integral-hw6:latest bash
```

Внутри выполните `make`; для независимых участников используйте пример ниже в той же оболочке. В этом локальном образе нет Python: `make test` предназначен для Linux с Python 3.

## Запуск

В первых двух реализациях один вызов создаёт все процессы:

```sh
./build/fork-named --config configs/conflict.conf
./build/fork-unnamed --config configs/overwater.conf
```

Для третьей и четвёртой реализаций сначала запустите координатор. Пример для `ordinary.conf` (один цветок, один садовник) в одной оболочке:

```sh
d=./build/independent-mq
"$d/server" --config configs/ordinary.conf &
```

После строки `READY` введите:

```sh
"$d/flower" 1 &
"$d/gardener" 1 &
wait
```

Для третьей реализации замените в первой команде `independent-mq` на `independent-shm`. Фоновые команды запускает оболочка. Координатор в этих двух реализациях сам участников не создаёт. Те же команды можно вводить в отдельных терминалах Linux: запустите каждый файл на переднем плане без `&`. В контейнере все участники должны находиться **в одном контейнере**.

| Файл в `configs/` | Цветов / садовников | Что видно в журнале |
|---|---|---|
| `ordinary.conf` | 1 / 1 | Заявка, полив и восстановление |
| `conflict.conf` | 8 / 4 | Разные садовники могут выбрать одну заявку; обслуживает один |
| `drought.conf` | 3 / 1 | Пока садовник занят, цветы в очереди засыхают |
| `overwater.conf` | 1 / 1 | Повторный полив внутри защитного интервала приводит к гибели |

Номера каждой роли начинаются с 1. Например, для `conflict.conf` после `READY` вместо двух команд участников выполните:

```sh
for i in 1 2 3 4 5 6 7 8; do "$d/flower" "$i" & done
for i in 1 2 3 4; do "$d/gardener" "$i" & done
wait
```

Отсчёт времени начинается, когда зарегистрирован последний участник. Без параметров — 3 цветка, 2 садовника и 40 тактов. `--help` показывает все параметры. Параметры задаёт координатор: аргументы командной строки важнее файла `key=value`. `--delay-ms` задаёт длительность такта; при 0 используется 10 мс.

События и строка `SUMMARY` идут в терминал координатора и `events.log` (можно задать `--log файл`). Программа останавливается по времени, при гибели всех цветов или по Ctrl+C. Для демонстрации Ctrl+C запустите на переднем плане `./build/fork-named --config configs/ordinary.conf --unlimited true --delay-ms 100`. Для независимого варианта удобнее нажать Ctrl+C в терминале координатора. Сохранится `reason=interrupted`, код выхода координатора — 130.

## Что показать в коде

- `src/main.c`: процесс цветка читает своё состояние и выбирает действие. Садовник запрашивает старейшую заявку, затем отдельной командой пытается её забрать, ждёт окончания своего полива и сообщает о завершении. Между выбором и подтверждением может успеть другой садовник.
- `src/model.c`: `flower_action` вызывается в процессе цветка. Общую запись о заявках и владельцах ведёт координатор; он проверяет, не устарела ли команда, и пишет журнал. Восстановление и защита от перелива работают как в ИДЗ-2.
- `src/ipc.c`: есть три семафора — право занять место для обмена, «запрос готов» и «ответ готов». Садовник освобождает место до начала полива, поэтому разные цветы могут поливаться одновременно. В версии с очередью сами данные проходят через `mq_send`/`mq_receive`, без разделяемой памяти.
- `src/config.c`, `src/io.c`: разбор параметров и запись результатов взяты из ИДЗ-2. В `tests/run.py` — четыре сценария и Ctrl+C для каждой реализации, включая проверку очистки IPC. Отчёт — в `docs/REPORT.pdf`.
